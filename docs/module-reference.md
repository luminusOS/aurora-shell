# Module reference

This table follows `MODULE_CATALOG` order. “On” and “off” are the GSettings defaults for a fresh schema. Every current module uses desktop role and session scope; none declares a runtime capability requirement. A module may still wait for an optional Shell surface or service before attaching UI.

| `wiggle-cursor` | `module-wiggle-cursor`: on | A quick shake of at least four short strokes, with no mouse button held, shows the current cursor, resampled and sharpened, in a 5x overlay, and keeps it there while the back-and-forth continues (two strokes are enough). Option types, defaults, and labels live in each manifest and the GSettings schema. Use the [module guide](modules.md) when changing them; the documentation test requires this table's keys to match the catalog exactly.

Wiggle Cursor does not change the configured desktop cursor theme or size. Ordinary themed cursor shapes and their tracker hotspots are supported. The tracker only exposes the cursor as the pixels Mutter rasterised at the cursor size times the monitor scale (commonly 32 px, 64 px on a 2x monitor), which also covers the SVG cursor themes of GNOME 51, but the vector itself is not reachable from an extension and cannot be re-rendered at 5x. The module reads those pixels once per cursor image, resamples them with GdkPixbuf's high-quality filter, applies an unsharp mask, and caches the result; until it is ready the unprocessed texture is shown. The public tracker does not expose Wayland viewport crops or buffer transforms, so those specialized cursor surfaces may not match native geometry. A second visibility inhibitor acquired during enlargement is not observable through the public API; the overlay can persist until the shaking stops or a supported reset, but releases only its own inhibitor.
